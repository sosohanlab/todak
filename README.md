# 토닥 수정본

GitHub 업로드·커밋·배포 없이 만든 로컬 수정본입니다. 기존 빚기·꾸미기·유약·굽기 과정과 한 대의 가마를 유지합니다.

## 실행

폴더를 압축 해제하고 `index.html`을 열면 제작과 3D 완성 화면을 사용할 수 있습니다. 권장 실행은 Python 3.10 이상에서 다음과 같습니다.

```sh
python server.py
```

브라우저에서 `http://127.0.0.1:8765`를 여세요. 이미지·스크립트는 파일 내용이 바뀌면 버전 주소가 갱신되고, 로컬 서버는 재검증 헤더를 보냅니다. Python 서버는 추가 패키지가 필요 없습니다.

## 적용한 기능

- 완성 화면을 Three.js PBR 렌더링으로 전환했습니다. 제작 중의 Canvas 방식은 유지합니다.
- 실제 바깥 반지름, 안쪽 반지름, 높이, 바닥 두께를 회전체 메시로 만듭니다. 바깥 그림·새김과 덧유약·빙렬·가마 결과를 기존 텍스처에서 가져옵니다.
- 금속성 0의 유약 재질, 거칠기, 미세한 요철, 물레 자국, 환경 반사, 입체 조명, 접촉 그림자를 적용했습니다.
- 스튜디오 / 나무 상판의 따뜻한 창가 / 어두운 갤러리 배경을 제공합니다. 실제 실내 사진을 합성한 기능은 아닙니다.
- 좌우 회전과 드래그, 휠·핀치 확대, 보기 초기화를 지원합니다.
- 2048px 정사각 작품 사진을 저장합니다. 카드·새 진열장 썸네일도 같은 3D 렌더러를 사용합니다. 기존에 저장된 썸네일은 원본 그림 데이터가 없어 자동 재생성하지 않습니다.
- 다 구운 작품은 가마 문을 눌러 공개합니다. 같은 모양·무늬를 유지한 다른 유약 작품은 기존 작품을 덮어쓰지 않습니다.
- 모바일은 메시·텍스처·그림자 해상도를 줄입니다. WebGL을 사용할 수 없으면 기존 Canvas 보기로 돌아갑니다.
- 생성형 이미지처럼 사용자가 만든 모양을 다른 도자기로 바꾸지 않습니다. 첨부한 생성 이미지와 동일한 사진 품질을 보장하는 구현은 아닙니다.

## 내 작품 이미지로 판매 제품 찾기 · Supabase 방식

검색 서버는 **Supabase Edge Functions**용으로 추가했습니다. 별도 Python 호스팅 없이 GitHub Pages와 연결할 수 있습니다. 설정은 **`SUPABASE_SETUP.md`**의 순서대로 진행하세요.

1. Supabase SQL Editor에서 포함된 마이그레이션 SQL 실행
2. Edge Functions Secrets에 `SERPAPI_API_KEY` 등록
3. `image-search` 함수 코드 배포와 공개 함수 JWT 설정 적용
4. `config.js`에 배포된 함수 URL만 입력

API 키는 Supabase 서버 Secrets에서 읽고 브라우저에는 보내지 않습니다. 같은 이미지 결과는 10분간 공유 캐시를 사용합니다. 기본 신규 검색 한도는 전체 월 200회·하루 20회, 같은 접속 주소 기준 하루 5회·분당 3회입니다. 한도는 Postgres에서 공통 적용하며 DB 설정이 없거나 장애가 나면 외부 검색을 실행하지 않습니다. 원본 작품 사진은 Supabase에 저장하지 않습니다.

실제 검색에는 SerpApi 키와 Supabase 프로젝트 설정이 필요합니다. 현재 `config.js`의 함수 주소는 비워 두었으며, 배포하지 않은 상태에서 '자동 검색이 작동한다'고 표시하지 않습니다. 연결 전에는 사진 저장·Google Lens 직접 검색을 사용할 수 있습니다.

기존 `server.py`는 로컬 미리보기와 이전 Python 검색 방식 호환용으로 남겨 두었습니다. Supabase를 연결하면 Python 검색 프록시는 사용하지 않습니다.

## 같은 파일명으로 바꿔도 캐시 갱신

배포 전에 다음 명령을 실행합니다.

```sh
python tools/refresh_assets.py
```

`og.png`, 아이콘, JavaScript, manifest 등 로컬 파일 내용을 SHA-256으로 계산해서 `?v=내용해시`를 붙입니다. **같은 파일명이라도 내용이 바뀌면 URL이 바뀝니다.** 변경이 없으면 버전값도 유지됩니다. OG와 Twitter 이미지의 버전 주소는 HTML에 직접 기록되므로 JavaScript를 실행하지 않는 크롤러도 읽을 수 있습니다.

`.github/workflows/pages.yml`은 향후 main에 업로드할 때 해시 갱신 후 Pages 배포를 자동으로 수행하는 설정입니다. 사용하려면 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택해야 합니다. 이번 작업에서는 GitHub 설정을 바꾸거나 파일을 업로드하지 않았습니다. 기존 '브랜치에서 배포' 방식을 유지한다면 업로드 전에 위 명령을 직접 실행해야 합니다.

카카오톡 등 공유 서비스는 **페이지 메타데이터도 자체 캐시**합니다. 해시 버전 변경은 이미지 캐시 재사용을 막지만, 이미 만들어진 대화방 미리보기까지 강제로 바꿀 수는 없습니다. 새 배포 뒤에도 이전 미리보기가 보이면 해당 서비스의 링크 미리보기 캐시 갱신 기능을 사용해야 합니다. HTML 자체의 캐시 정책은 실제 호스팅 서버 설정에도 영향을 받습니다.

## 검증 범위

- Python 테스트: 실제 이미지 바이트 업로드/이미지 ID 검색 요청, 판매 후보 필터, 빈 결과, 미설정 키, 허용되지 않은 Origin 거절, 같은 파일명 이미지 교체 시 OG 버전 변경과 반복 실행 안정성.
- 데스크톱·모바일 크기의 DOM 시뮬레이션: 시작 → 단일 가마 → 직접 공개 → 3D 메시·유약 재질 생성 → 배경 선택 → 진열장 → 유약 변형 → 검색 연결 실패 처리.
- GPU가 필요한 실제 WebGL 화면·반사 품질·모바일 기기 성능의 시각 검수는 실행 환경 제한으로 완료하지 못했습니다. DOM 검증에서는 WebGL 출력만 대체하고 실제 Three.js 메시·재질 데이터는 사용했습니다.
- Supabase 함수 요청 처리·DB 한도 검사를 추가했습니다. 외부 검색과 실제 Supabase 배포는 키·프로젝트 미제공으로 실행하지 않았습니다.

개발 검증은 `npm install` 후 `npm test`로 실행할 수 있습니다. 일반 사용에는 Node나 npm 설치가 필요 없습니다.

Three.js는 별도 다운로드 없이 실행하도록 `vendor`에 포함했습니다. 라이선스는 `vendor/THREE-LICENSE.txt`를 참고하세요.
