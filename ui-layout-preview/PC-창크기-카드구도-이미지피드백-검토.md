# PC 창 크기·카드 구도·이미지 피드백 수정

## 바뀐 동작

- 상단 제작 단계는 클릭, Enter, Space로 이동한다. 편집 단계 사이에서는 형태와 그림을 유지한다. 굽는 중에는 이동을 막고 완성은 가마를 연 뒤 표시한다. 튜토리얼의 진행 조건도 유지한다.
- 같은 크기의 캔버스에 width/height를 다시 대입하지 않는다. 버튼 클릭 때 캔버스가 지워지는 경로를 제거했다.
- 가마의 겹친 온도 중 상단 HTML 표시를 숨기고 가마 조절기의 온도만 남겼다.
- PC의 검색 창은 최대 640px, 카드 창은 620px, 내 진열장은 1040px로 제한한다. 작은 화면에서는 바깥 여백과 스크롤을 유지한다. 진열장 작품 상세가 열려도 선반의 높이가 눌리지 않는다.
- 카드 창을 열면 현재 작품 위치·크기·배경으로 즉시 다시 그린다. 저장 렌더러가 위치를 중앙으로 초기화하지 않도록 수정했다.
- 완성 화면의 배경 선택을 이미지 미리보기가 있는 창으로 교체했다. 미보유 항목은 가격·포인트 부족을 표시하고 명시적인 구매 버튼으로 결제한다. 닫기와 취소는 포인트를 사용하지 않는다. 현재 무료 배경의 가격은 바꾸지 않았다.
- 상점은 보유 여부만 표시한다. 선택 테두리와 사용 중·적용됨 표시를 없앴다. 구매 자체는 현재 배경·진열장 선택을 바꾸지 않는다. 실제 선택은 완성 화면의 배경 선택과 내 진열장의 진열장 선택에서 한다.
- 완성 후 검색 창이 지연해서 자동으로 뜨던 동작을 제거했다. 검색 버튼으로 열 수 있다.
- 바닥의 그림·새김 좌표 방향을 편집 화면과 일치시켰다. 바닥 새김의 법선 재계산이 몸통 전체를 바꾸지 않도록 하고, 평평한 바닥의 가장자리 법선과 렌더링 해상도를 보정했다. 새 렌더러 주소와 진열장 썸네일 버전을 바꿔 이전 캐시도 갱신한다.

## 검색 서버

새 주소의 CORS 사전 요청이 403으로 차단되고 있었다. 정식 주소와 이전 주소를 허용하면서 기존 추가 허용 주소도 유지했다. 임의의 외부 주소는 계속 차단한다. 실제 정식 주소에서 잘못된 입력은 400, 정상 이미지 검색은 200과 검색 결과 8개를 확인했다. 한도 설정은 늘리거나 해제하지 않았다.

## 피드백 이미지

이미지 1장을 선택·미리보기·삭제할 수 있다. PNG/JPEG/WebP와 입력 파일 10MB까지 지원하고 긴 변을 최대 1600px로 줄여 JPEG로 변환한다. 전송 이미지는 약 500KB 이내이며 메타데이터를 재사용하지 않는다. 잘못된 파일·형식 위장·과도한 크기는 전송 전에 또는 서버에서 거부한다.

이미지는 공개 주소 없이 기존 비공개 피드백과 함께 저장하고 운영자 메일의 JPEG 첨부로 전달하도록 구현했다. 기존 전송 제한과 중복 방지 접수번호를 유지한다. 실패하면 작성 내용과 이미지가 남고, 성공 후 새 의견에는 이전 이미지가 남지 않는다.

## 검증 범위

`check-latest-ui.cjs`: 320×568, 390×844, 1440×900, 2560×1440에서 실제 단계 이동, 키보드, 그림 유지, 캔버스 초기화, 카드 구도 변경, 창 너비, 구매·취소·포인트 부족을 검사한다.

`check-feedback-images.cjs`: 320·390·1440 너비에서 파일 선택, 크기 축소, 미리보기·삭제, 실패 후 동일 접수번호로 재시도, 성공 후 초기화를 검사한다. 네트워크 전달 성공·실패는 응답을 대체해 재현한다.

서버 단위 검사에서는 실제 전송 요청의 JPEG 첨부 내용과 잘못된 입력 차단을 검사한다. DB 저장·권한 검사는 롤백하는 트랜잭션으로 확인했고 익명 방문자는 피드백을 읽거나 직접 쓸 권한이 없다. 운영자 메일함의 실제 수신 확인은 별도다.

Chrome과 터치 에뮬레이션을 사용했다. 실제 휴대전화 운영체제 공유창과 기기별 GPU 성능을 모두 검증한 것은 아니다.
