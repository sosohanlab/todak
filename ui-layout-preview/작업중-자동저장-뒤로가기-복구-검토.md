# 제작 중 작업 자동 저장과 앱 복구

기존에는 완성 작품만 진열장 저장소에 남고, 제작 중 상태는 실행 중 메모리에만 있었다. 이번에는 완성 작품과 별개인 `todak.work-in-progress.v1`과 IndexedDB `todak-work-in-progress`에 현재 물레 작업 한 개를 저장한다. 기존 진열장과 이전 주소 가져오기의 자료는 변경하지 않는다.

손을 뗀 뒤, 설정 변경 뒤, 홈으로 돌아갈 때, 앱이 숨겨질 때와 주기적 저장을 사용한다. 모양·안쪽 공간·높이·바닥·거친 표면·도전 횟수·유약·직접 고른 색·담그기 깊이·선택한 도구와 제작 단계를 저장한다. 옆면 그림과 새김, 윗면 그림, 밑바닥 그림과 새김의 다섯 이미지는 원본 PNG로 저장한다. 바뀌지 않은 이미지는 재사용해 매 프레임 인코딩하지 않는다.

localStorage에는 즉시 저장하고 IndexedDB에도 순서대로 보관한다. 둘 중 하나가 막혀도 다른 저장소로 복구할 수 있다. 시작할 때 최신 기록을 확인한 뒤 홈의 ‘하던 작업 이어하기’를 활성화한다. 아직 작업이 없는 첫 방문에는 이 버튼을 보이지 않는다. 복구한 작업은 완성 작품으로 새로 등록하거나 진열장에 중복 추가하지 않는다. 튜토리얼 진행·도전 횟수·가마 상태도 함께 복구하며, 새 조작의 되돌리기 이력은 새로 시작한다.

제작에 들어갈 때 앱 내부 방문 기록을 추가한다. 작업 중 휴대폰/브라우저 뒤로가기는 우선 홈으로 돌아가며 작업을 초기화하지 않는다. 저장·검색·진열장 같은 창이 열려 있으면 해당 창부터 닫는다. 홈에서도 다시 나가 앱이 종료되면, 다음 실행의 이어하기로 복구한다.

## 검증

- Chrome 390/1440: 실제 빚기 후 뒤로가기→홈→현재 작업 복귀, 창 종료→새 창→저장본 복구.
- 종료 시 저장 콜백을 차단한 상태에서도, 이미 자동 저장된 모양·다섯 이미지의 모든 픽셀·직접 고른 유약색·깊이·도구와 보기가 같은지 비교한다.
- IndexedDB가 막힌 경우와 localStorage가 용량 오류를 내는 경우를 각각 재현해 대체 저장소로 복구한다.
- 도전 횟수와 본, 튜토리얼 진행, 굽기 도중과 완성 후의 복구, 진열장 작품 수가 중복 증가하지 않음을 확인한다.
- 현재 완성 작품을 진열장에서 실제로 깨뜨린 뒤에는 해당 임시 저장도 제거되어 이어하기로 되살아나지 않는지 확인한다. 다른 제작 중 작업과 다른 진열장 작품은 유지한다.
- 기존 홈 진입·튜토리얼, 일반 제작·완성 사진·진열장 흐름을 회귀 검사한다.

검증은 Chrome의 모바일 화면/터치 환경과 브라우저 재실행으로 수행한다. 기기의 저장소 삭제·앱 데이터 초기화·시크릿 모드 종료에 따른 데이터 삭제까지 보존하는 기능은 아니다. 이 변경 전에 이미 종료되어 저장되지 않은 작업은 새로 복구할 자료가 없다.
