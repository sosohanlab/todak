# 토닥 UI·튜토리얼 최종 검토

## 반영한 추가 수정

- 튜토리얼은 동작을 완료해도 자동으로 넘어가지 않는다. 같은 도구로 더 연습한 뒤 말풍선의 **다음 안내**를 누른다. 빚기·꾸미기·유약 단계의 마지막에는 기존 다음 단계 버튼으로 이동한다.
- 왼쪽 진행창의 현재 과제를 기존 코발트색 영역으로 강조했다. 작은 모바일에서는 진행표가 줄바꿈되지 않게 줄이고, 실제 안내창 높이를 기준으로 도자기 위 여백을 확보했다.
- PC 말풍선을 실제 조작 대상 가까이에 배치했다. 잘못된 대상을 가리키던 꼬리를 수정하고, 좁은 PC 작업 영역에는 안내 공간을 확보했다. 도구창에서 색상·질감을 고르는 동안 벽의 도구통을 잠시 숨겨 말풍선 자리를 비운다.
- 색상·유약을 선택할 때 도자기는 원래 밝기로 보인다. 강조 영역은 도자기 윤곽과 실제 버튼의 크기·모서리를 따른다.
- 바탕색 → 반짝임 → 담그기·표면 무늬 → 붓칠 순서를 유지했다. 홈의 튜토리얼 시작·중단·이어하기·처음부터를 확인했다.
- 두 손가락 확대가 윗면·밑바닥·붓 유약에서 그리기로 처리되던 문제를 수정했다. 확대에 따른 불필요한 붓 자국과 되돌리기 기록을 없앴다. 이미 한 손가락으로 그리던 획은 두 손가락으로 전환해도 유지한다.
- 꾸민 작품을 다시 빚기로 가져간 뒤 되돌리기·다시하기를 해도 옆면·윗면·밑바닥·새김 레이어가 보존되도록 확인했다.

전체 버튼 검사는 **55개 시나리오에서 6,084회 클릭·955회 입력·7,064개 UI 상태 확인**을 통과했다. 화면별 집계는 [최종 검토 결과](최종-검토-결과-2026-11-16.json)에 기록했다.

추가로 도구창 높이 조절·접기·재열기·스크롤·가로세로 전환, 카드 입력과 닫기, 사진 크기·배경·360도 감상, 상점과 언어 전환, 가마 굽기부터 진열장 재열기까지 확인했다. 피드백 오류·입력 보존·재시도는 가짜 서버 응답으로 검사했다.

## 검토 방법과 한계

Chrome에서 실제 클릭·키보드·휠·터치 이벤트를 사용했다. 모든 저장·그리기는 격리된 검사 브라우저의 가짜 작품으로 진행했다. 기존 사용자의 진열장이나 작품을 검사 데이터로 바꾸지 않았다.

모든 기기·브라우저·무한한 버튼 순열을 보장하는 검사는 아니다. 위의 화면 크기와 도달 가능한 주요 버튼 조합을 검증했다. 실제 Android/iPhone 하드웨어, 운영체제의 색 선택·공유창, 외부 서비스의 최종 전송은 자동 검사의 범위 밖이다.

검사 중 로컬 빌드 파일 교체가 겹친 반응형 실행은 최종 파일을 고정해 다시 돌렸다. 긴 획의 400ms 체크포인트를 고려해 짧은 획과 전체 레이어 복구를 각각 검사했고, 깎기 검사는 실제 흙 변화가 생긴 뒤 복구 경계를 검증한다. 첫 실패 기록과 재검증 여부는 회귀 검사 결과에 함께 남겼다.
