# 튜토리얼 자동 진행과 검색 대기 개선

## 최종 동작

튜토리얼 안의 다음 안내·입력 완료·사진 확인 버튼을 없앴다. 36개의 학습 행동은 실제 조작을 마치면 이어지고, 포인터 또는 슬라이더 방향키를 누르는 동안에는 넘어가지 않는다. 빚기·꾸미기·유약의 마지막에는 딤드를 모두 해제하고 충분히 연습한 뒤 기존 꾸미러 가기·유약 바르기·가마에 넣기 버튼으로 이동한다. 완료한 뒤 도구를 다시 바꾸거나 되돌리기를 사용해도 연습할 수 있다.

유약의 자동 기본 선택으로 바탕붓 안내를 건너뛰던 경로를 막았다. 바탕붓과 유약 붓은 실제 선택해야 다음 안내가 나오며, 이미 선택된 붓을 다시 눌러도 선택이 해제되지 않는다. 정상 자유 제작·도전의 기본 도구 선택은 유지한다.

저장 창 말풍선의 홈으로 버튼을 제거했다. 제목·용도는 글을 쓰다 잠시 멈췄다는 이유로 넘어가지 않고, 입력칸을 떠나거나 Enter·실제 저장 버튼을 사용할 때 이어진다. 용도는 비워도 저장할 수 있다. 저장 완료는 실제 저장/공유 요청이 성공한 뒤 처리하며, 창을 닫는 실제 동작으로 이어진다. 창 밖에서는 기존 홈 복귀·이어하기를 쓸 수 있다.

완성 사진은 꺼내는 연출과 실제 렌더링이 준비된 뒤 360도 안내로 이어진다. 검색은 결과·결과 없음·오류 안내가 나올 때까지 완료되지 않는다. 내용은 실제 닫기 버튼을 누를 때까지 볼 수 있고, 검색을 기다리기 어렵다면 창을 닫고 튜토리얼을 이어갈 수 있다.

## 이미지 검색

검색 사진을 640px JPEG로 준비해 미리보기와 요청에서 재사용한다. 같은 사진의 성공 결과를 현재 작품 세션 안에서 최대 12개를 10분 동안 보관해 재검색 시 외부 요청 없이 보여준다. 작품·장식·색상·배경·각도·크기·사진 위치가 달라지면 새 사진을 만들고, 새 작품을 시작하면 캐시를 초기화한다. 실제 이미지 기반 검색과 서버 횟수 제한은 유지한다.

기다리는 동안 경과 시간을 표시한다. 창을 닫아도 요청과 결과는 유지하며 자동으로 창을 다시 열지 않는다. 서버 CORS 사전 요청은 브라우저가 재사용할 수 있도록 86400초 캐시한다. 서버의 인증 방식·쿼터·비공개 데이터 접근은 변경하지 않는다.

수정 전 최근 성공 요청 3건의 서버 처리 시간은 10.497~11.025초(평균 10.825초)였다. 외부 제공자의 첫 검색 시간을 즉시 없애는 변경은 아니다. 반복 요청과 중복 사진 준비를 줄이고 기다리는 상태를 분명히 하는 변경이다.

## 검증

- Chrome 390·830·1440·2560 너비: 실제 붓질 후 자동 진행, 조작 중 대기, 제작 단계 마지막 연습, 실제 붓 선택, 지연된 사진, 입력·저장·닫기, 검색 응답 대기와 반복 검색 캐시.
- 같은 사진은 서버 요청 1회만 사용하고, 배경·각도를 바꾸면 새 요청을 사용하는지 확인한다. 캐시 처리 시간은 Node/브라우저 간 통신 시간을 제외한 브라우저 이벤트 내부에서 측정한다.
- 8개 화면 크기에서 강조 영역·말풍선·저장 창 배치와 홈 복귀·이어하기를 검사한다. 4개 PC 크기에서 단계 끝의 실제 버튼이 회전 중에도 고정되는지 검사한다.
- 전체 36개 학습 행동의 상태 흐름, 유약의 작업 순서와 기본 제작·저장 흐름을 회귀 검사한다. WebGL을 대체하는 상태 검사는 Chrome의 실제 렌더링 대기 검사로 보완한다.
- 검색 서버의 CORS·입력 검증·횟수 제한·서버 캐시·실제 사진 업로드 연결을 포함한 18개 단위 검사와 운영 사전 요청 확인.

브라우저 검사는 Chrome과 화면 크기 에뮬레이션 기준이며, 모든 실제 기기와 GPU를 검사했다는 의미는 아니다. 검색 속도 UI 검사는 지연시킨 모의 응답으로 재현하며 유료 검색을 반복 실행하지 않는다.
